| 项 | 值 |
|---|---|
| 文件 | `D:\20533\deskbox\files\Nexus OS 26 宣传片\audio\source_audio.mp3`（60.952s，与参考片同源音轨） |
| 拍点表 | 同目录 `beat-map.json`：`tempo_bpm 123.05`、`period 0.4876`、`phase 0.205`、125 拍、含 onset 强度 |
| 公式 | `beat(n) = 0.205 + 0.4876 × n`；重拍 = `n % 4 == 0`；5.991s 处为全片最强重音（strength .992） |

**同步方式（必须照做）**：`bgm.currentTime` 是唯一主时钟。每帧 `t = bgm.currentTime`，把 `t` 交给状态机求每段的局部进度，动画本身不由 WAAPI/CSS 的 duration 计时（否则会出现「样片那种一帧内完成」的问题）。起播时用 `performance.now()` 对齐一次偏移，之后只信音频时钟。

**降级**：音频加载失败 / `play()` 被自动播放策略拦截 / 用户静音 → 切到 `performance.now()` 单一时钟，从同一起点起算，节拍表一字不改；标签显示「声音 待开启」，下一次用户手势重试起播。任何情况下动画都按节拍表准点完成，不卡住、不错拍。

### 4.2 零重叠 / 零溢出

- 所有元素建立后先 `pause()`，再按 `t` 写 `currentTime`；同一时刻只允许一个「主运动焦点」，辅助元素位移幅度 ≤ 主焦点的 35%。
- 自检函数：枚举可见元素（`.dock-item, .dock-separator, #finder-bar > *, .window, .desktop-icon, .widget, .shard, .guide, .focus`），两两求 rect 交叠，交集任一边 > **1.5px** 判违规；任一 rect 超出 `#frame`/视口（含负坐标）判溢出。
- 扫描节奏：`t = 100ms → 总长`，逐点断言；样片里 80 点扫描曾做到 0 违规，方法可直接复用（脚本 `n26_final.js`）。
- 反例教训：六块 160×100 卡片 3×2 同时在动的方案判「吵」，已废弃；新方案同一时刻只有一块在变形。

### 4.3 reduced-motion 降级

`matchMedia('(prefers-reduced-motion: reduce)')` 命中时：**不创建任何关键帧动画**，只做一次性 300ms 交叉淡入（`opacity` only），总时长 0.3s，不进节拍状态机，也不播配乐。验收输出应为 `done|元素数|0`（0 = 动画对象数）。

### 4.4 跳过怎么收尾

点击任意处 / `Esc` / 失焦 → 调 `skip()`：停时钟、停配乐、把所有节点写回终态（`opacity/transform` 清零、`display` 恢复），移除 `body.n26fb-active`，`requestAnimationFrame` 一帧后解除 `n26-busy`。要求：**收尾不产生二次动画**，一帧内到位，且不得把 Dock 的 `translateX(-50%)` 或 `.entering/.dock-enter` 状态留在节点上。

### 4.5 与既有入场过渡的统一

`enterDesktop()` 自带的 600ms `desktopEnter / dockEnter / finderEnter` 必须被压制（首次进入时），否则两套过渡打架。做法：注入的 style 块里 `body.n26fb-active #desktop.entering{animation:none!important}`、`body.n26fb-active #dock.dock-enter{animation:none!important}`、`body.n26fb-active #finder-bar.finder-enter{animation:none!important}`，由构建动画接管；正常解锁（非首次）完全不激活 `n26fb-active`，走原生过渡。

## 五、安全性（用户硬要求）

- **只准插入**：一个独立 `<style>` + 一个独立 `<script>`（统一前缀 `n26fb-`），加一处挂载调用；**不许整体重写、不许改其他段落一个字节**。
- 改前备份到 `_backups\`（带时间戳），并记录基线 SHA-256。
- 改后对非本块段落做逐段哈希比对，只允许出现「新增块 + 挂载行」两处差异；出问题整块删除即可还原。
- 写入前确认文件静置：与 Dock 放大、个性化重排两条线共用同一文件，**取 mtime + 哈希，若已变则重新取基线**。

## 六、验收标准与复验方法

### 6.1 通过标准

1. 真桌面节点逐个显形：构建段内不允许出现任何「代理图形」，也不允许真实桌面提前整屏闪现。
2. 逐点扫描（100ms 步长）0 重叠、0 溢出，且每段可见推进（位移 ≥0.35px 或 opacity ≥0.02）。
3. 每镜头 ≥1 拍且 ≥350ms；无「一帧内完成」段。
4. 运镜可读：每段至少一次推进或横移，四层视差方向一致、幅度不同。
5. 跳过：点击/Esc 后一帧内回到终态，无二次动画、无残留。
6. `prefers-reduced-motion`：0 个动画对象。
7. 配乐：起播对齐、可静音、断网/被拦截时按内部节拍准点完成。
8. 浅色/深色各一遍，均通过。

### 9.2 两条死约束的落实

- **时间源**：`t = bgm.currentTime`（`play()` 成功后按 `performance.now()` 对齐一次），降级才用内部时钟；每帧 `stateAt(t)` → 写 inline 样式。core 里没有 rAF / setTimeout / WAAPI / CSS duration；任意 t 可独立 seek（11 个采样点两次求值完全一致）。
- **真节点**：`#dock` / `.dock-item` / `.dock-separator` / `#finder-bar` 两段及子项 / `#desktopIcons .desktop-icon` / `.desktop-widget` 全部直接操作主壳原有 DOM；窗口骨架复用真实 `.window` + `.window-titlebar` + `.window-content` 结构与 CSS，结束即移除。自绘的只有「辅助线 / 聚焦框 / 指针 / Covi」这类构建过程可视化（`kind:'guide'`）。
- 贴边 UI 用**独立 transform 属性** `translate`/`scale` 写入，不覆盖 `#dock` 的 `transform: translateX(-50%)`。
