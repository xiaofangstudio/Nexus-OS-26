### 1.3 冲突（会互相抢事件，必须先解决）

| # | 冲突 | 位置 | 后果 | 处理 |
|---|---|---|---|---|
| 1 | canvas `wheel` 无条件缩放 | 星空、天气地球 | 全局滚动层一接管就同时缩放/滚动 | 全局层遇到 `canvas` **直接放行**，由应用 `claim` |
| 2 | 图片查看器任意滚轮都缩放 | `apps/image.html` | 用户无法用滚轮纵向滚动；与全局惯性叠加会抖 | 改为 `ctrlKey`/捏合才缩放，普通滚轮平移或放行 |
| 3 | 锁屏滚轮上推解锁 | 主壳 `#lock-screen` | 全局层会把解锁滚轮吃掉 | 锁屏可见时**整个手势层暂停** |
| 4 | 启动台滚轮翻页 | 主壳 `#launchpad` | 双指横滑会被判成三指手势，翻页失效 | 启动台内 `data-n26-gestures="off"`，或三指识别要求在非滚动区 |

| 7 | `ctrl + wheel` 同时是浏览器页面缩放 | 浏览器壳层 | 不拦截会把整个 OS UI 放大 | 全局层默认 `preventDefault`（`blockPageZoom=true`） |
| 8 | 教程舞台 `wheel` `preventDefault` | `n26-tour.js` | 弹窗打开时背景无法滚动（预期内） | 引导层加 `data-n26-gestures="off"` |

### 1.4 三个必须写进设计里的现实约束

1. **浏览器拿不到手指数。** `wheel` 事件没有 `touches`，三指/四指在 Windows 上通常被系统手势吃掉。所以三指只能靠「滚轮爆发形态」推断，默认**关闭**，由设置显式开启。
2. **iframe 应用收不到主壳的手势。** `apps/*` 是独立文档，主壳的 `window.addEventListener('wheel')` 对它无效。接入方式只有两条：应用自己 `<script src="../ui/n26-gestures.js">`，或主壳在 `iframe` load 时同源注入。
3. **Web 没有旋转手势。** 双指旋转无法从 `wheel` 还原。相册「旋转」只能保留按钮 / 快捷键 / 双击，不能承诺双指旋转。

## 二、全局手势映射表（建议默认值）

事件类型统一为：`scroll` / `bounce` / `pinch` / `pinchend` / `swipe3` / `edge` / `dragstart` / `drag` / `dragend` / `drop`。
优先级：**应用 claim > 系统默认 > 原生行为**。

| 手势 | 物理动作 | 识别条件 | 系统默认行为 | 应用覆盖点 | 失败时 |
|---|---|---|---|---|---|
| 双指上下滑 | 两指平移 | 非 `ctrl`，`deltaY` 主导 | 最近可纵向滚动祖先：归一化 + 惯性 + 边缘阻力 | 设置/商店：只调摩擦；画布：`claim` 自己缩放 | 放行原生滚动 |
| 双指横滑 | 两指横移 | 非 `ctrl`，`deltaX` 主导 | 最近可横滚祖先横向滚动；没有则不动 | 方哩方哩 rail、tabs、时间线 | 放行原生 |
| 双指捏合 | 张 / 合 | `ctrlKey + wheel`，或 Safari `gesturechange` | 命中图片/画布/地图则内容缩放（以光标为锚点），否则不缩放整个 UI | 相册、地图、Strata/Reelix、浏览器页面 | 无命中：吞掉页面缩放（可配） |
| 三指上滑 | 三指上推 | 滚轮爆发：≤300ms、`|Δy|≥384`、非滚动区 | 打开启动台 | 应用可拦截（如全局搜索） | 不动 |
| 三指下滑 | 三指下推 | 同上反向 | 显示桌面（最小化全部窗口） | 应用可拦截 | 不动 |
| 三指左/右滑 | 三指横扫 | ≤420ms、`|Δx|≥240`、`|Δx|>1.5|Δy|`、非滚动区 | 切换上一个 / 下一个应用 | 应用声明 `data-n26-gesture-3="history"` 时改为前进/后退 | 不动 |
| 左边缘右滑 | 从屏幕左缘向内 | 指针起始 x ≤ 26px，手指右拨（`deltaX<0`，`|Δx|>30`），`|Δy|<30` | 当前窗口「返回」 | 浏览器 / 文件管理 / 未来的阅读器 | 无历史：轻微回弹提示 |
| 右边缘左滑 | 从屏幕右缘向内 | 指针起始 x ≥ 屏宽-26，手指左拨（`deltaX>0`，`|Δx|>30`） | 当前窗口「前进」 | 同上 | 同上 |
| 轻点拖拽 | 一指按住 + 另一指轻滑 | 一指 `pointerdown` 按住不动，另一指位移（合成 pointermove 或独立 pointer）> 4px | 拖动窗口 / 图层 / 文件，`data-n26-drop` 吸附 | 相册排序、桌面图标、Strata 图层 | 未超阈值：当作点击；不需要长按 |
| 长按拖动 | 按住 280ms 后移动 | 现有 DockNav 逻辑 | 保留不变（导航排序） | — | — |

键盘兜底（手势不可用时仍可用）：`Ctrl+↑` 启动台、`Ctrl+↓` 显示桌面、`Ctrl+←/→` 切换应用、`Ctrl+Tab` 切换器。

## 三、教程改写方案（本轮不改 `n26-tour.js`，等确认）

现状问题：`welcome_b` / `tap_b` / `tap_drag` 反复强调「不用按住，也不用拖动」，而拖拽恰恰是系统必需能力。建议 7 步：

1. `welcome`：改为「先认识一下精准触控板」——**滑动移动、轻点选中、按住拖动**，三件事一句话说完。
2. `tap`：保留轻点，删掉 `tap_drag` 里「不用按住拖动」的否定句，改为「按住再移动，就是拖动」。
3. **新增 `drag`**：一张卡片，按住中心圆点拖到右侧虚线框，教「按住 → 移动 → 松手」。
4. `wheel`：改为真实列表滚动（带惯性），文案提「两指滑 = 滚动，越滑越快会有一点惯性」。
5. `pinch`：保留，补一句「捏合只缩放你看的内容，不会放大整个系统」。
6. `swipe`：改为「双指横滑 = 横向切换；三指横扫 = 换应用」，并说明三指需在设置里开启。
7. `done`：补「左边缘右滑返回、右边缘左滑前进」两个边缘手势。

文案原则：**只描述正向动作，不再出现「不要拖动」**；每个手势配一句「失败了会怎样」（放行原生，不会卡住）。

### 已知 Web 限制

1. 三指 / 四指的真实手指数读不到，只能按滚轮事件流形态推断，因此默认关闭、设置里显式开启。
2. 跨域 iframe（外部网页、在线视频）内的 wheel / pinch 不冒泡到主壳，无法接管。
3. 双指旋转没有标准事件，画布旋转只能走应用内控件。
4. 鼠标滚轮与触控板只能靠「连续事件流 vs 离散一格」推断，极少数高频滚轮会被当成触控板。

## 六、语义修正（v1.1.0 · 拖动与横向方向）

### 6.1 拖动：一指按住不动 + 另一指轻滑

- 语义：按住的那根手指负责「按住」，另一根手指的滑动负责「位移」；**不需要长按，也不要求同一点持续按压位移**。
- 实现（`ui/n26-gestures.js` `enableDrag`）：一指 `pointerdown` 后挂 window 级 `pointermove`；第二根手指若被浏览器报成独立 pointer，登记为 `alt`，其位移同样驱动拖拽。Windows 精准触控板会把「按住那指不动 + 另一指滑动」合成为同一 pointer 的 `pointermove`，因此两条路径都命中。
- 教程（`ui/n26-tour.js`）：5 语言文案统一改为「第一根手指按住不动，第二根手指轻滑」；删除「按住别松手 / 按下拖动」等描述；并如实注明「若设备只给浏览器上报一根手指，按住卡片用同一根手指轻滑，结果一样」。
- 判定只看「按住 + 位移 > 4px」，没有 `held < 60ms` 之类的时间门槛。

### 6.2 横向拨动方向（实测对照）

自然滚动下 `手指方向 = -deltaX`。改前的 `edge` / `swipe3` 直接拿 `deltaX` 当手指方向，`setupSwipe` 也是 `dx += deltaX`，于是右拨变成左移。

| 场景 | 改前 | 改后（实测） |
|---|---|---|
| 教程横滑：二指从左往右拨 | 圆点左移（反） | `dotX = +88`（到最右，过关） |
| 教程横滑：二指从右往左拨 | 圆点右移（反） | `dotX = -88`（到最左，过关） |
| 演示页小球：`deltaX=-80`（手指右拨） | 左移 | 小球 `x: 0 → +40.8` |
| 演示页小球：`deltaX=+80`（手指左拨） | 右移 | 小球 `x: +40.8 → +26.7`（左移） |
| 左缘向内（手指右拨，`clientX=8`） | 判成前进 / 不触发 | `edge left`，window 返回 |
| 右缘向内（手指左拨，`clientX=1432`） | 判成返回 / 不触发 | `edge right`，window 前进 |

验证环境：Playwright + 系统 Edge，1440×900；主壳教程 7 步逐步真实操作通过（轻点 / 拖动 / 滚轮 / 捏合 / 横滑 / 完成），两套拖动路径（合成单 pointer、两根独立 pointer）均过关。
