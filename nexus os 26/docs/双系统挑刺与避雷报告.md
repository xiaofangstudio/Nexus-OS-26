## 1. 结论摘要

### 1.1 FluentOS：最狠的 5 条

1. **文件名可触发存储型 XSS，且严格 CSP 默认关闭。** 桌面图标用 `innerHTML` 直拼文件名（`R1\js\ui\desktop.js#L590`），重命名只拦 `/` 和 `\`（`R1\js\apps\files.js#L1026`），CSP 严格模式默认 `false`（`R1\js\core\csp.js#L25-33`）。改个文件名就能在桌面执行脚本，读走 localStorage 里的 PIN 与设置。
2. **大文件被静默截断，用户以为存住了。** 超过 128KB 的内联图片/2MB 的其他载荷会在写入和读取时被替换成标记（`R1\js\core\storage.js#L15-16`、`#L46-60`、`#L82-90`），文件内容变空且无任何提示。
3. **“已自动保存”是假的。** 记事本调用 `State.updateFS` 后不看返回值就显示“已自动保存”（`R1\js\apps\notes.js#L1038-1045`）；底层写失败只 `console.error` 并返回 `false`（`R1\js\core\storage.js#L95-97`）。配额满/隐私模式下刷新即回滚。
4. **一半“系统开关”是演出。** “定位服务”只写不读（`R1\js\apps\settings.js#L3534-3536`，全仓仅 2 处命中且都在写入侧）；控制中心 Wi-Fi 只改 `dataset`、不写 State（`R1\js\ui\controlcenter.js#L63-76`），默认还是 `data-active="true"`（`R1\index.html#L413`）。
5. **登录安全是纸糊的，失败还没有出路。** PIN 明文存在设置里并直接比较（`R1\js\ui\login.js#L140`），三次失败后只把 `security-link` 显示出来，全仓没有任何 click 绑定（grep `securityLink` 仅 show/hide），无锁定、无延时。

### 1.2 Nexus OS 26：最狠的 5 条

1. **关掉的窗口刷新后会复活。** `closeWindow` 只从内存/DOM 删除、不写存档（`R2\Nexus OS 26.html#L30649-30693`），启动时 `restoreWindows()` 无条件回放上次快照（`#L26876`、`#L27028-27055`），而快照只在“磁贴排列/注销”时写（`#L27020`、`#L50441`）。复现：开两个窗 → 关一个 → F5 → 两个都回来。
2. **多个设置项是死开关，而且有代码可证。** 动画速度写入 `--anim-mult` 后全文件无人消费（`#L42275`，grep 仅此一处）；“显示文件扩展名”只有默认值和开关写入两处（`#L20567`、`#L39076`）；控制中心音量写 `n26_cc_volume`（`#L47194-47199`），音频路径读的是 `settings.soundVolume`（`#L20684`），两者从不同步。
3. **“密钥不出宿主”与 README 相反。** `apps\agent.html` 先把宿主 `ai_config.key` 回填到输入框（`#L366-388`），发请求时直接带 `Authorization: Bearer <key>`（`#L691-693`），完全绕过宿主已提供的 `aiChat` 代理（`R2\Nexus OS 26.html#L29033` 起）。
4. **虚拟机的“完全隔离/关机即焚”不成立。** `apps\vm.html#L192` 的 iframe 没有 `sandbox`，`#L211` 直接加载 `../Nexus OS 26.html`；同源同 localStorage，而内置初代系统在“恢复出厂”里执行 `localStorage.clear()`（`apps\vm-os1\Nexus OS.html`，1 处命中），会把宿主的账户/文件一起清空。
5. **截图不是“真实捕获”，小游戏是“目录的目录”。** 截图走 `html2canvas` 重绘 DOM（`R2\Nexus OS 26.html#L55755`，另见 `#L23949`、`#L29242`），iframe 区域会截成空白；小游戏 iframe 加载的是落地页 `../../../工具与小游戏.html#id`（`apps\games.html#L222`、`#L292`），还得在里层再点一次“开始游戏”链接（`工具与小游戏.html#L892`）。README 说 45 款，代码里是 47 条，且有一条是“在 OS 里再开 OS”。

## 2. FluentOS 的刺（逐条）

### F-01【致命·真 bug】文件名存储型 XSS，CSP 默认关闭

- **现象**：把文件/文件夹重命名为 `<img src=x onerror=alert(1)>`，回到桌面刷新，图标渲染时执行。
- **证据**：
  - `R1\js\ui\desktop.js#L590`：`el.innerHTML = \`<img ... alt="${node.name}" ...><span>${node.name}</span>\``，`node.name` 未转义。
  - `R1\js\apps\files.js#L1026`：重命名校验只判 `value.includes('/') || value.includes('\\')`。
  - `R1\js\core\csp.js#L25-33`：`strictCspEnabled` 默认 `false`，页面无默认 CSP。
- **为什么是问题**：这是 Web 桌面，设置、PIN、会话都在 localStorage；一次文件名注入即可读走并伪造 UI 操作。不是“伪系统就无所谓”的问题，宿主浏览器同源。
- **避雷**：所有来自用户数据的名称必须走 `textContent` 或统一 `escapeHtml`；文件名在入口处做白名单；默认启用 CSP（至少 `script-src 'self'`）；重命名/导入要有危险字符测试。

### F-02【高·真 bug】大文件静默截断，且读取时再次改写

- **现象**：导入一张 >128KB 的图片/一个 >2MB 的文本，当时可用；重启后文件内容变空、桌面预览消失，没有提示。
- **证据**：`R1\js\core\storage.js#L15-16`（阈值 128KB/2MB）、`#L46-60`（正则把 `"content":"data:..."` 换成 marker）、`#L63-72`（标记 `encoding='external-data-removed'`）、`#L82-90`（写入时也截断并 `console.warn`）。
- **为什么是问题**：为了启动性能牺牲用户数据的完整性，但没有 UI 告知，也没有迁移到 IndexedDB/Blob；这是“看起来能存，其实存不住”的典型。
- **避雷**：二进制一律进 IndexedDB/OPFS；写入前做配额预估并明确报错；禁止静默修改用户内容；启动清理逻辑只清理“可再生成”的缓存，不碰用户文件。

### F-03【高·真 bug】“已自动保存”不校验结果

- **现象**：配额满/隐私模式/存储异常时，记事本仍显示“已自动保存”，刷新后内容回滚。
- **证据**：`R1\js\apps\notes.js#L1038-1045` 调 `State.updateFS` 后直接写状态文案；`R1\js\core\state.js#L605` 丢弃 `Storage.set` 返回值；`R1\js\core\storage.js#L95-97` 失败仅 `console.error` 并返回 `false`。
- **为什么是问题**：保存状态是用户信任的核心；显示成功但实际失败，比直接报错更糟。
- **避雷**：持久化 API 必须返回 `boolean/Result`，UI 状态只能由结果驱动；失败要有阻塞式提示 + 重试 + 导出兜底。

### F-04【高·真 bug + 能力缺失】隐私/网络开关是演出

- **现象**：设置里关掉“定位服务”，天气仍直接请求定位；控制中心 Wi-Fi 开关刷新后永远回到“已连接”。
- **证据**：
  - `R1\js\apps\settings.js#L3534-3536` 写入 `locationEnabled`；全仓仅这两行命中，无消费者；`R1\js\apps\weather.js#L603` 无条件 `navigator.geolocation.getCurrentPosition`。
  - `R1\js\ui\controlcenter.js#L63-76` Wi-Fi 点击只改 `dataset.active` 和副标题，不发 State；`R1\index.html#L413` 默认 `data-active="true"`。
  - 蓝牙虽写了 `bluetoothEnabled`，但没有配对/扫描后端（`R1\js\apps\settings.js#L3253` 起）。
- **为什么是问题**：这是“隐私承诺”类开关，用户会按字面理解。伪系统可以没有真实网卡，但不能让开关与行为脱钩。
- **避雷**：每个开关必须有单一状态源、至少一个消费者、关闭后行为可验证；做不到就标“仅演示”，或直接删掉开关。

### F-05【高·真 bug】登录安全：PIN 明文 + 三次失败死链接

- **现象**：控制台可直接读 `fluentos.settings.pin`；连续输错三次后出现“安全问题”链接，点了没反应；无失败锁定/延时。
- **证据**：`R1\js\ui\login.js#L140`（`State.settings.pin || '1234'`）、`#L157-174`（仅计数与显示）、`#L168-170`（只 `securityLink.classList.remove('hidden')`）；grep `securityLink` 全仓只有 show/hide，无 click handler；`R1\index.html#L230` 只是链接容器。
- **为什么是问题**：伪系统的登录是“演示”，但界面把它包装成安全边界；失败路径的设计比没有更糟。
- **避雷**：要么明确标注“演示锁屏，无安全作用”，要么做真正的凭据校验（Passkey/WebCrypto）；任何错误路径上的按钮都必须可执行，否则删掉。

### F-06【高·能力缺失】后台冻结只冻视觉，计时器照跑

- **现象**：最小化媒体/时钟窗口后，后台仍按 250ms/10s 的节奏跑定时器。
- **证据**：`R1\js\ui\window.js#L474-499` 只做事件派发；`R1\css\main.css#L3470-3479` 仅 `pointer-events:none` 并隐藏 PWA iframe；`R1\js\apps\media.js#L2654`、`R1\js\apps\clock.js#L1056` 的 interval 未见对应的暂停分支。
- **为什么是问题**：这是 README 明确宣传的能力（“后台冻结”）；只冻交互不冻计算，长时间开机会积累 CPU 与耗电。
- **避雷**：定义统一 `pause()/resume()` 生命周期，最小化/隐藏时调用；不要用 CSS 假装冻结；用 `visibilitychange` + `content-visibility` 双保险。

### F-07【中·真 bug】对话框/模态没有焦点与语义

- **现象**：打开 Modal/Dialog 后 Tab 仍能跑到背景，Esc 不能关，读屏不播报；关闭按钮 `alt="关闭"` 写死中文。
- **证据**：`R1\js\core\fluent-ui.js#L706-735`（Modal）与 `#L810-889`（Dialog）：无 `role="dialog"`、`aria-modal`、focus trap、Esc；`#L713` 硬编码 `alt="关闭"`，`#L815-825` 默认标题“提示/成功/警告/错误”写死中文。
- **为什么是问题**：模态是系统级组件，a11y 缺口会扩散到所有应用；英文界面还会混中文。
- **避雷**：组件库层面统一实现 `role/aria-modal/labelledby` + focus trap + Esc + 恢复焦点；文案全部走 `t()`。

### F-08【中·真 bug】窗口可拖出屏幕左/右缘

- **现象**：把窗口拖到屏幕右缘之外，窗口标题栏可能不可见；只能靠任务栏/快捷键找回。
- **证据**：`R1\js\ui\window.js#L1074-1080` `_clampWindowBounds` 只对 `top` 做 `Math.max(0, ...)`，`left` 原样返回，`width/height` 只保底不封顶。
- **为什么是问题**：窗口位置记忆 + 多显示器/小窗口场景会放大；恢复成本高。
- **避雷**：四边都钳制，且保证至少 N px 标题栏在可视区；监听 `resize` 重新钳制。

### F-09【中·能力缺失】浏览器白屏无法解释

- **现象**：访问禁止 iframe 的站点（X-Frame-Options/CSP）后，标签页永久空白，没有提示、没有“新窗口打开”出口。
- **证据**：`R1\js\apps\browser.js#L576-593` 普通 iframe + 仅 `load` 监听；注释 `#L579-582` 自己承认“Browser tabs intentionally use a regular iframe”；无法区分“加载失败”和“被拒绝嵌入”。
- **为什么是问题**：README 已说明限制，但 UI 层没有把限制变成可理解的状态；用户只会认为浏览器坏了。
- **避雷**：加载超时 + “无法嵌入，点此新窗口打开”兜底；能预检的 URL 直接走外部窗口；不要把白屏当加载中。

### F-10【中·演示差距】App Shop 安装是 5 秒空等

- **现象**：点安装后固定等 5 秒，没有进度、不能取消；关掉窗口仍会“装完”。
- **证据**：`R1\js\apps\appshop.js#L2233` `const installDelay = 5000`；`#L2263` 按剩余时间 `setTimeout`。
- **为什么是问题**：这是演示动画冒充下载过程；用户无法判断卡死还是进行中。
- **避雷**：要么真实请求 + 进度 + 取消，要么把“演示安装”写在按钮上；禁止固定延时假装网络。

### F-11【中·安全】第三方 PWA 的 sandbox 在同源目录下失效

- **现象**：受信任目录/允许 localStorage 的第三方应用同时拿到 `allow-same-origin` 和 `allow-scripts`，可访问父页存储。
- **证据**：`R1\js\third_parts_apps\pwa-loader.js#L364-366`：`sandbox = ['allow-scripts','allow-popups','allow-forms','allow-modals']`，`trustedCatalog || allowLocalStorage` 时 `unshift('allow-same-origin')`。
- **为什么是问题**：README 把第三方应用描述为“独立 iframe 窗口运行”；同源+脚本等于没有隔离。
- **避雷**：第三方默认 `allow-scripts` 不给 `allow-same-origin`；需要存储时走 `postMessage` 桥，而不是放宽 sandbox。

### F-12【中·真 bug】进程管理把虚构进程当真实系统进程

- **现象**：进程列表永远有 7 个“Shell Host / Notification Broker / VFS”等进程，PID 固定；内存只有 Chromium 的 `performance.memory`。
- **证据**：`R1\js\apps\process-manager.js#L16-24` 硬编码 `CORE_PROCESSES`（PID 104/216/328...）；`#L459-467` 内存读取仅 Chrome 可用；`#L485-488` PID 由哈希生成。
- **为什么是问题**：这是“演示 vs 真实”的边界；把虚构数据包装成资源监控，会误导用户做判断。
- **避雷**：区分“系统服务（模拟）”和“应用实例（真实）”，给模拟项加标识；无法测量的指标显示“不支持”，不要造数。

### F-13【中·真 bug/低】天气请求不检查 HTTP 状态、无超时

- **现象**：接口 4xx/5xx 或挂起时，页面停在骨架/旧数据；失败只发通知，没有内嵌重试。
- **证据**：`R1\js\apps\weather.js#L647-649` 直接 `fetch` + `res.json()`，无 `res.ok`、无 `AbortController`、无 timeout；`#L672-675` 失败仅 `addNotification`。
- **为什么是问题**：天气是联网应用，弱网是常态；错误态是首屏体验的一部分。
- **避雷**：统一 `fetchJson` 封装（超时/重试/状态码）；页面内错误卡片 + 重试按钮；缓存最后成功数据并标注时间。

### F-14【中·设计一致性】组件“假复用”，各应用各写一套

- **现象**：App Shop 详情弹层自己实现 overlay（无 Esc/焦点管理），记事本/照片/计算器各自带私有翻译字典，32 个应用内联 `<style>`。
- **证据**：`R1\js\apps\appshop.js#L2719-2740` 自建 `appshop-detail-overlay/modal`；`R1\js\apps\notes.js#L16-251` 私有 i18n 字典；`R1\js\apps\process-manager.js#L503-516` 内联样式。
- **为什么是问题**：主题、a11y、i18n 无法统一治理；修一个组件要改 N 处。
- **避雷**：明确“壳组件”与“应用私有样式”的边界；弹层/对话框/工具栏只允许用 `FluentUI`；应用内联样式只允许布局微调，不允许重定义组件外观。

### F-15【中·性能】首屏全量加载与材质开销

- **现象**：53 个脚本一次性 `defer` 加载（约 2.9MB JS），Theme 资源 29.5MB；CSS 里 252 处 `backdrop-filter`；OOBE 前串行预载约 17.2MB。
- **证据**：`R1\index.html#L494-546`（脚本清单，全部 `defer`）；实测 `js` 目录 2928KB、`Theme` 29.5MB、`css\*.css` 中 `backdrop-filter` 252 处；`R1\js\ui\boot.js#L727-735` 分组预载。
- **为什么是问题**：低端机/移动端首屏与拖拽会明显掉帧；Fingo、开发者中心等非首屏模块也被首屏解析。
- **避雷**：按需加载（Fingo/开发者中心/第三方目录延迟到首次打开）；材质分档（低配降级为半透明纯色）；图片 WebP/AVIF + 响应式尺寸。

### F-16【低·i18n】英文界面仍会冒出中文

- **现象**：英文语言下登录成功通知是“登录成功/欢迎回来”，对话框按钮/标题是中文。
- **证据**：`R1\js\ui\login.js#L153-155` 硬编码；`R1\js\core\fluent-ui.js#L713`、`#L815-825`、`#L895` 中文默认值；`R1\js\main.js#L1860` 等处原生 `confirm/alert`。
- **为什么是问题**：i18n 是“全有或全无”的体验，漏一两处就会显得不可信。
- **避雷**：加一条 CI 检查：`js/` 下除 `i18n.js` 外禁止出现 CJK 字符串（白名单注释/正则除外）。

### F-17【低·文档矛盾】开发指南与实现相反

- **现象**：指南说“不要使用 defer”，入口却全部 `defer`。
- **证据**：`R1\docs\DEVELOPER_GUIDE.md#L65`（“不要使用 defer、async”）vs `R1\index.html#L494`（全部 `defer`）。
- **为什么是问题**：新贡献者按文档改会踩全局加载顺序坑。
- **避雷**：文档用脚本校验（`validate-project.ps1`）覆盖关键规则，禁止“文档说 A、代码做 B”。

### F-18【低·真 bug】窗口/锁屏常驻 1s 计时器

- **现象**：登录后锁屏与任务栏的 1s interval 仍在跑，未随可见性暂停。
- **证据**：`R1\js\ui\lockscreen.js#L47`、`R1\js\ui\taskbar.js#L40`。
- **为什么是问题**：小成本但持续；伪系统长时间挂着更明显。
- **避雷**：所有全局 tick 统一调度器，`visibilitychange` 时暂停/恢复。

## 3. FluentOS 真正值得学的优点（含移植注意事项）

### S-01 组件级生命周期定时器 `wTick`
- **它怎么做的**：`R1\js\ui\widget-defs.js#L144-157`，interval 每次触发先判 `el.isConnected`，元素被移除就 `clearInterval`，不需要调用方记得清理。
- **为什么值得学**：小组件是“频繁增删”的场景，漏清理是内存泄漏高发区；把清理责任放进调度器，比靠开发者自觉可靠。
- **移植到 Nexus 要怎么改才不违和**：Nexus 的小组件/窗口是 DOM + iframe 混合，`isConnected` 对 iframe 内部无效；需要把“容器存活”和“应用存活”分开，iframe 侧用 `postMessage` 心跳或 `visibilitychange`，否则会出现“窗口关了，iframe 里的计时器还在跑”。

### S-02 异步渲染的统一错误壳 `wAsync`
- **它怎么做的**：`R1\js\ui\widget-defs.js#L159-170`，先渲染 loading，失败统一渲染错误行，并再次判 `isConnected` 防止写回已卸载节点。
- **为什么值得学**：把“加载/失败/卸载”三态收口到一个包装器，应用代码只写成功路径。
- **移植注意**：Nexus 的错误态大量是“一行文本”或静默；直接搬这个壳会显得太素，需要配 `docs\UI硬标准.md` 的错误卡片样式，并加“重试”与“新窗口打开”出口。

### S-03 设置单一入口 + 按 key 应用
- **它怎么做的**：`R1\js\core\state.js#L604-640` 的 `updateSettings` 统一落盘，再按 key 触发 `applyTheme/applyBlur/applyVolume` 等应用器。
- **为什么值得学**：避免“设置面板写一个键、运行时读另一个键”的分裂（Nexus 正在犯这个错）。
- **移植注意**：必须把“写入结果”回传（F-03 就是反面教材）；应用器要幂等，重复调用不产生副作用。

### S-04 API Key 加密存储
- **它怎么做的**：`R1\js\core\fingo.js#L307-338`，PBKDF2-SHA256 120000 轮派生 + AES-GCM 256，随机 salt(16)/iv(12)，失败明确抛错。
- **为什么值得学**：把密钥保护做进存储层，而不是靠“UI 不显示”。
- **移植注意**：口令丢失即不可恢复，必须在 UI 明示并给导出/重置路径；Nexus 的 `agent.html` 连“回填 + 直发”都没绕开，直接搬加密只会掩盖问题，先改调用链。

### S-05 资源清单 + 统一校验脚本
- **它怎么做的**：`R1\scripts\generate-resource-manifest.ps1`、`generate-storage-manifest.ps1`、`validate-project.ps1`，对入口、资源引用、清单哈希、JS 语法做 `-Check` 校验（README `#L166-177`）。
- **为什么值得学**：纯静态项目没有打包器，最容易出现“文件删了引用还在”“清单过期”；用脚本把发布前检查固化。
- **移植注意**：Nexus 是单文件 + 大量 iframe 应用，清单可以按“应用目录 + 桥 API 版本”生成；先解决 `bak/before/__p_*` 混入分发的问题，再谈校验。

### S-06 OOBE 分级预载
- **它怎么做的**：`R1\js\ui\boot.js#L727-735` 按 core → 插图 → 图标 → 壁纸分组串行，失败可降级（OOBE 文案 `R1\js\ui\oobe.js#L153` 明确提示“部分资源暂未缓存”）。
- **为什么值得学**：首启体验的“确定性”比“全部预载完”更重要。
- **移植注意**：Nexus 首屏是直接进桌面，没有 OOBE 缓冲，照搬会拉长白屏；应改为“桌面先出、非核心资源空闲加载”，并把 17MB 级素材换成按需缩略图。

### S-07 跨应用虚拟文件系统 + 统一拖放协议
- **它怎么做的**：`R1\js\core\cross-app-drag.js`、`R1\js\core\file-import.js`，桌面/文件/应用之间用统一的 `application/fluent-file` 拖放载荷（`R1\js\ui\desktop.js#L104-107` 的 `hasFluentPayload`）。
- **为什么值得学**：伪系统最容易做成“每个应用一个孤岛”；统一 MIME/拖放协议让“文件”成为系统能力。
- **移植注意**：Nexus 目前是各应用自己读 localStorage 文件树（`image.html#L565`、`video.html#L656` 等各写一份遍历）；先抽宿主 `FS` API，再谈拖放，否则只是把孤岛连成一张网。

## 4. Nexus 的刺（系统壳 + 应用分区）

### 4.1 系统壳

#### N-01【致命·真 bug】关闭窗口不落盘，刷新后复活
- **现象**：开两个窗口，关掉一个，按 F5，被关掉的窗口回来了；窗口位置/尺寸也不会记住。
- **证据**：`R2\Nexus OS 26.html#L30649-30693` `closeWindow` 全程无 `setUserLS('windows')`；启动 `#L26876` 调 `restoreWindows()`；`#L27028-27055` 直接套用存档坐标；`windows` 仅在磁贴排列 `#L27020` 与注销 `#L50441` 写回。拖拽/缩放结束 `endDrag` `#L31470-31515` 同样只改内存。
- **影响**：用户对“关窗/布局”的信任归零；每次刷新回到旧现场，像幽灵窗口。
- **修复方向**：`closeWindow` 成功后立即写 `windows`（节流）；`endDrag/endResize` 结束写一次；启动恢复时过滤不存在/越界窗口。

#### N-02【高·真 bug】设置死开关群（动画速度/扩展名/音量/亮度）
- **现象**：
  - 动画速度“快/正常/慢”切换后无任何变化。
  - “显示文件扩展名”开关无效果。
  - 控制中心音量滑块不影响任何声音；调到 0 也不是静音。
  - 亮度调到 40%，刷新后滑块显示 40%，实际亮度 100%。
- **证据**：
  - `#L42081` 定义 `animSpeed`，`#L42161-42163` 三个选项；`#L42275` `root.style.setProperty('--anim-mult', mult)`，全文件 `--anim-mult` 仅此一处，无 CSS 消费。
  - `#L20567` 默认 `showFileExt:false`，`#L39076` 开关写入；grep 仅这两处，无读取。
  - `#L47194-47199` 音量只写 `n26_cc_volume`；音频读 `#L20684` `(s.soundVolume || 50)/100`（`0` 被 `||` 吞成 50）；设置滑块 `#L39623` 是另一个值。
  - `#L47200-47205` 亮度直接 `document.body.style.filter='brightness()'`；`n26ccSync` `#L47237-47276` 恢复时只回填滑块，不重设滤镜。
- **影响**：用户会反复调、反复怀疑系统；比“没有这个设置”更伤。
- **修复方向**：每个设置项建立“写入键 → 消费者 → 可见行为”三元组；CI 加 grep 检查；音量统一到 `soundVolume` 并修 `||` 默认值；亮度持久化并在启动时重放。

#### N-03【高·能力缺失】FangUI 四套皮肤只覆盖壳，深色令牌根本不触发
- **现象**：切到 `neu-solid/neu-glass` 后，桌面壳变了，应用还是原来的脸；深色模式下部分 FangUI 组件仍是浅色。
- **证据**：`R2\fangui\core\tokens.css#L61`/`#L77` 暗色令牌只在 `[data-mode="dark"]` 下；主壳 `Nexus OS 26.html` 中 `data-mode` 命中 0 次，只切 `body.dark-mode`（`#L45192`）；`fangui\core\neu.css` 中 `body.dark-mode` 0 次、`data-mode` 11 次；24 个应用 HTML 中仅 `alarm.html`、`_template.html`、`_ui-demo.html` 引用 `fangui/core`（`Select-String` 统计）。
- **影响**：README 的“四套皮肤统一”不成立；用户切皮肤只得到“半套主题”。
- **修复方向**：壳与令牌统一用 `data-mode`（或同时写两种）；应用通过共享样式入口强制继承；给“未适配”的应用加降级外观，而不是放任各写一套。

#### N-04【中·真 bug】通知不持久、角标不清零
- **现象**：刷新后通知全空；手动关掉一条通知，通知中心历史里它还在，红点也不消失。
- **证据**：`#L32687` `let notificationHistory = []`；`#L32733-32739` `dismissNotification` 只移除 DOM、不动数组；红点只看 `notificationHistory.length`（`#L33898`、`#L33903`），所以关掉通知后历史与红点都不会变；全文件无 `setUserLS('notifications')` / `setLS('notifications')` 命中。
- **影响**：通知中心是“系统可信度”的展示面，刷新即失忆。
- **修复方向**：持久化最近 N 条 + 已读状态；角标由未读数驱动，而不是数组长度。

#### N-05【中·能力缺失】可访问性只做了“局部补丁”
- **现象**：Dock/窗口/启动台基本无法用 Tab 操作；设置里的文字放大只影响两处；高对比度是白名单选择器。
- **证据**：主文件 58k 行中 `aria-label` 仅 14 处、`@media` 仅 8 条、`onmousedown` 9 处（拖拽/缩放全鼠标）；`ui\n26-a11y.js#L592-615` 主要给 `.fu-switch`/`.a11y-chip` 加 Enter/Space，未覆盖 Dock/窗口；`ui\n26-a11y.css` 的文字缩放只作用于 `.window-content` 与 `#settingsPanel`；24 个应用中 17 个 `aria-*/role` 计数为 0（weather、games、alarm、calculator、monitor、screenshot、agent、terminal 等）。
- **影响**：不是“少一点”，而是键盘用户无法完成基本操作。
- **修复方向**：先做壳层键盘模型（Dock/窗口/菜单/对话框焦点陷阱），再逐应用补；a11y 规范加进 `docs\UI硬标准.md` 的可判定条款。

#### N-06【中·性能/体积】单文件 3.36MB、58k 行，令牌 0 使用
- **现象**：改一个字号要全文替换；启动解析全部内联脚本；备份文件与应用素材把分发体积推到 50MB+。
- **证据**：`Nexus OS 26.html` 实测 3,192,009 字符 / 58,130 行；`var(--fs-*` 命中 0，`font-size:` 1606 处，hex 色值 2039 次；`backdrop-filter` 345 处；`setInterval` 56 处；根目录 `bak/before` 文件合计 16.7MB；`apps` 合计 36.6MB，其中 `float` 27.3MB（`.build` 与 `assets` 疑似重复）。
- **影响**：可维护性、首屏、低配机帧率三输。
- **修复方向**：拆分壳/设置/桥为独立脚本；令牌强制化（先替换高频项）；清理 `.bak/before/__p_*`；`float` 去重。

#### N-07【中·设计系统自相矛盾】“唯一真值源”与实际实现冲突
- **现象**：`docs\UI硬标准.md#L11` 写“`ui/tokens.css` 是唯一真值源”，但主壳几乎不用令牌；同一系统里存在 `settings.style`（`body.style-glass/flat/skeu`）与 `settings.fanguiStyle`（`html[data-ui]`）两套风格开关，可互相覆盖。
- **证据**：`R2\Nexus OS 26.html#L9` 注释“主文件 :root 变量优先”；`#L2` 默认 `data-ui="liquid"`，`fanguiStyle` 在 `#L27701`、`#L27758` 应用；另一套 `applyUIStyle` 在 `#L40835`、`applyOSStyle` 在 `#L40897` 操作 `body.style-*`；`docs\UI硬标准.md#L31-33`（M-01/M-03）要求只用令牌。
- **影响**：设计师/开发者无法判断“以哪个为准”，新应用只会继续漂移。
- **修复方向**：保留一套风格状态机，另一套只做兼容映射；把 `UI硬标准` 的条款变成 lint。

#### N-08【低·真 bug/隐私】`getSetting` 不过滤，`getSettings` 才过滤
- **现象**：第三方应用通过桥 `getSetting` 能拿到任意设置，包括自定义壁纸/锁屏壁纸的完整 dataURL。
- **证据**：`R2\Nexus OS 26.html#L29067` `case 'getSetting': return p.key ? st[p.key] : st`；对比 `#L28836` `n26BridgeFilterSettings` 与 `#L28914` `getSettings` 的过滤路径。
- **影响**：与“密钥/隐私不出宿主”的设计初衷冲突。
- **修复方向**：`getSetting` 走同一白名单；敏感键（壁纸 dataURL、API 配置）默认拒绝。

#### N-09【低·分发/版本】相对路径与版本号漂移
- **现象**：只拷贝 `nexus os 26` 子目录分享，图标/默认壁纸 404；界面注释写 v3.0，运行时版本是 v2.9.67。
- **证据**：主文件 71 处 `../` 引用（如 `#L19176` 起 `../Desktop icon/`）；`#L51657` `NEXUS_OS_VERSION='v2.9.67'`，而 `#L17516` 等处注释写“★ v3.0”。
- **影响**：分享即坏图；版本叙事不可信。
- **修复方向**：资源路径改为项目内相对路径或内联；版本号单一来源并在 UI/注释统一。

#### N-10【中·演示差距/技术债】Dock Bar 2.0 只有一个应用接入，却存在四套 Dock
- **现象**：README 说 Dock Bar 2.0 “全落地、第一方第三方同一套”，实际全仓只有截图应用调用 `dockbar`；其余应用从不显示这条“独占亮点”。同时页面里并存 `#dock`、`#dockBar`、`#n26LeftDock`、`#n26RightDock` 四套 Dock 容器。
- **证据**：`README.md#L28`、`#L32` 宣称 Dock Bar 2.0；`apps\screenshot.html#L427`、`#L430`、`#L433` 是全仓唯一的 `dockbar` 调用点；主文件 `#L19173`（`#dock`）、`#L19211`（`#dockBar`）、`#L19214`（`#n26LeftDock`）、`#L19239`（`#n26RightDock`）。
- **影响**：一个“差异化卖点”实际是截图应用的专属工具条；四套 Dock 增加状态同步与布局回归成本。
- **修复方向**：要么把 Dock Bar 接进音乐/视频/监视器等场景（README 已有计划），要么把宣传降到“截图录屏专用”；四套 Dock 合并为一套可换边实现。

### 4.2 应用层

#### A-01【致命·假功能】Reelix / Strata 桌面版文件 IO 全死
- **现象**：打开、保存、导入素材、导出都无反应；界面只剩内置示例。
- **证据**：`R2\apps\reelix\index.html#L1`（单行打包）含 `__TAURI_INTERNALS__` 2 处；`R2\apps\strata\index.html#L1` 含 3 处；调用 `invoke` 在浏览器返回 `undefined`；全包无 `showOpenFilePicker`/`indexedDB` 兜底。
- **影响**：2.1MB / 2.3MB 的“专业应用”实际是桌面版未适配的空壳，属于凑数。
- **修复方向**：接 Web File API/OPFS，或下架并在 README 标注“桌面版专用”。

#### A-02【致命·隔离失效】虚拟机不是隔离，且可能清空宿主数据
- **现象**：虚拟机内一切与宿主同源；“关机即焚”只是文案；初代系统“恢复出厂”会执行 `localStorage.clear()`。
- **证据**：`R2\apps\vm.html#L192` `<iframe id="vmFrame">` 无 `sandbox`；`#L211` `src:'../Nexus OS 26.html'`；`#L159`/`#L189`/`#L259`/`#L275` 反复承诺“完全隔离/关机即焚/内存已清空”；`R2\apps\vm-os1\Nexus OS.html` 中 `localStorage.clear()` 1 处。另 README 说“可拖入本地 .html”，`vm.html` 无 `drop/dragover`。
- **影响**：数据互相覆盖是最高级别的事故；用户会真的把实验数据放进去。
- **修复方向**：`srcdoc` + `sandbox="allow-scripts"`（去掉 `allow-same-origin`）+ 独立存储前缀；恢复出厂只删本前缀键；拖入功能要么实现要么删文案。

#### A-03【致命·与 README 相反】AI 密钥直发
- **现象**：`agent.html` 里能看到并直接使用宿主 API Key；网络面板可见 `Authorization` 头。
- **证据**：`R2\apps\agent.html#L366-388` 读取 `ai_config` 并回填 `#agKey`；`#L691-693` `fetch(..., headers:{Authorization:'Bearer '+AI.key})`；宿主已有 `aiChat` 代理 `R2\Nexus OS 26.html#L29033` 起；README `#L21`/`#L33` 承诺“密钥不出宿主”。
- **影响**：安全承诺失效；任何同页脚本/用户都能拿到 Key。
- **修复方向**：应用内不保存/不回填 key，只调 `Nexus.aiChat`；桥侧做 key 脱敏返回。

#### A-04【高·UX/凑数】小游戏是“目录的目录”
- **现象**：点游戏 → iframe 打开落地页对应 section → 还要再点“开始游戏”链接；超时提示只会让你“新窗口打开”。
- **证据**：`R2\apps\games.html#L222` `SRC='../../../工具与小游戏.html'`；`#L292` `fr.src = SRC + '#' + id`；`#L293-299` 3.5s 超时；`工具与小游戏.html#L878-895` 每个 section 只是介绍 + `<a href="贪吃方.html">`。`games.html#L171-219` 列表 47 条，README `#L34` 说 45 款。
- **影响**：多一次跳转、多一层失败点（`file://` 跨目录 iframe 常被拦）；“收录 45 款”名不副实。
- **修复方向**：直接 iframe 目标游戏 HTML；把 47 条与 README 对齐；删掉 `nexusos`（OS 里开 OS）。

#### A-05【高·演示差距】“真实截图”实为 DOM 重绘
- **现象**：截图里 iframe 应用区域是空白，视频/网页材质也不是像素级；录屏才是真捕获。
- **证据**：`R2\Nexus OS 26.html#L55755` `html2canvas(target, options)`（另见 `#L23949`、`#L29242`）；录屏 `#L29296-29298` `getDisplayMedia`。
- **影响**：与 README “真实捕获”不符；用户拿截图当证据会失真。
- **修复方向**：标注“DOM 截图”；或用 `getDisplayMedia` 单帧合成；至少对 iframe 区域提示“此区域不会出现在截图”。

#### A-06【高·状态】番茄钟刷新即失忆
- **现象**：计时中刷新/关窗，剩余时间和轮次全丢。
- **证据**：`R2\apps\pomodoro.html` 全文件 0 处 `getUserLS/setUserLS`；`#L331` `endAt:0`，`#L439` 只在内存写 `endAt`。
- **影响**：核心功能不可用。
- **修复方向**：持久化 `{endAt, remainMs, running, round}`，启动时按 `Date.now()` 续算。

#### A-07【高·状态】2048 只存最高分，不存棋盘
- **现象**：刷新后当前局消失，只剩最高分。
- **证据**：`R2\apps\game2048.html#L167` `score/best` 内存变量；`#L375-376` 只写 `game2048_best`；`#L509` 只读 best。
- **影响**：与 README “2048 大升级”不符。
- **修复方向**：存 `{board, score, best}`，加“继续上局”。

#### A-08【高·性能/数据】小说每 3 秒全量重写进度
- **现象**：读小说时每 3s 读一次 localStorage、再写回（含正文），长文会撞配额；失败被吞。
- **证据**：`R2\apps\novel.html#L286-295` 3s interval；`#L259-261` 写失败 `catch` 后重试更小对象。
- **影响**：卡顿、配额、丢进度。
- **修复方向**：只存 `{bookId, offset, updatedAt}`；用 `beforeunload` 冲刷；失败提示。

#### A-09【高·假功能】Necta 远控是演示
- **现象**：连接 900ms 后显示“信令未接通”；文件传输/画质/隐私屏只 toast；延迟硬编码。
- **证据**：`R2\apps\necta\app.js#L895-913` 自述“信令服务器还没部署”；`#L504` 固定 `S.latency || '—'`；`#L474-480` 磁贴仅提示。
- **影响**：用户以为能用，实际不能。
- **修复方向**：把未实现入口置灰并标“规划中”；或砍掉。

#### A-10【高·假功能】FangWork 检查更新/更新是假动作
- **现象**：“检查更新”固定 620ms 后提示；点“更新”只改字符串。
- **证据**：`R2\apps\fangwork.html#L302-321` 620ms `setTimeout`；`#L331` `applyUpdate` 只 `toast`。
- **影响**：软件管家最核心的能力是假的。
- **修复方向**：接真实版本清单（哪怕是静态 JSON）+ 下载 + 校验；否则改名为“应用启动器”。

#### A-11【高·联网/错误态】天气无超时、只缓存城市
- **现象**：断网/超时后白屏或停在一行文本，无重试；重开还得重新请求。
- **证据**：`R2\apps\weather.html#L305` `fetch` 无 `AbortController`；`#L311` 失败只写一行文本；`#L374` 只缓存城市名。
- **影响**：弱网下核心应用不可用。
- **修复方向**：超时/重试/错误卡片 + 缓存最后一次数据与时间戳。

#### A-12【中·假数据/联网】方哩方哩默认整站演示数据
- **现象**：未接后端时仍显示视频列表与播放，但都是内置演示源。
- **证据**：`R2\apps\bili\index.html#L6` 自述“未连接时自动回退到内置演示数据”；`#L1071` `API_BASE='https://ai.fanggame.company'`；另有 MDN/w3schools 演示 MP4。
- **影响**：与 README “不联网”矛盾；用户分不清真假内容。

#### A-13【中·联网】音乐依赖远端，离线只剩本地

- **影响**：宣称“本地优先”，实际核心曲库在远端。
- **修复方向**：把远端标为可选增强；本地导入/示例曲库要能独立完成一次完整体验。

#### A-14【中·浅功能】多邻国只有 12 个词
- **证据**：`R2\apps\duolingo.html#L264` 起 `WORDS` 词表（12 条）；`#L262` `ROUND = 8`；无 `speechSynthesis`/音频。

- **修复方向**：明确“单词卡小游戏”；加 `speechSynthesis` 与错题复习。

#### A-15【中·状态】速记 420ms 防抖且无卸载冲刷
- **证据**：`R2\apps\quicknote.html#L374` `setTimeout(flush, 420)`；无 `beforeunload`/`visibilitychange` 冲刷；双 key 迁移（`quicknotes_v2`/`quicknotes`）。

#### A-16【中·假数据】终端 `free/top/ps` 是常量
- **证据**：`R2\apps\terminal.html#L545-546` 固定 8192/2048/4096；`#L555` “真实系统监控见活动监视器”。
- **影响**：终端是开发者信任入口，假数据会误导。
- **修复方向**：标注“模拟”；或接宿主 `performance.memory` 并显示“不可用”。

#### A-17【中·死代码】HTML 应用读 `nexus_theme`，宿主从不写
- **证据**：`R2\apps\htmlapp\index.html#L169` `localStorage.getItem('nexus_theme')`；宿主全文件 0 处写入该键。
- **影响**：主题同步永不生效。

#### A-18【中·状态隔离】跨窗广播键直写 localStorage
- **证据**：`R2\apps\image.html#L961`/`#L966`（`n26ImageNow`/`n26ImageState`）、`video.html#L990`/`#L1018`、`music.html#L1446`/`#L1469`；宿主也直读（`Nexus OS 26.html#L46288` 区）。
- **影响**：切换账户后 A 的“正在播放/背景”泄漏给 B。
- **修复方向**：按 `user_<name>_` 命名空间；或用 `BroadcastChannel` 只在当前会话内传播。

#### A-19【中·重复实现】文件遍历/toast 各应用各写一份
- **证据**：`R2\apps\image.html#L565`、`video.html#L656`、`music.html#L788`/`#L929`、`terminal.html#L378`/`#L396` 各写 FS 遍历；7 个应用各写 `toast()`。
- **影响**：修一处配额/错误处理要改 N 处；行为不一致。
- **修复方向**：宿主提供 `FS.list/read/write` 与 `UI.toast`，应用只调桥。

#### A-20【中·文档造假/能力缺失】`sandbox.html` 声称已建，实际不存在
- **现象**：文档 `Dock Bar 与未尽需求.md#L15` 写“桌面沙盒 `apps/sandbox.html` ✅ 已建”，但 `apps` 目录 24 个 HTML 中没有该文件；注册表把 `sandbox` 静默重定向到 `vm`（`Nexus OS 26.html#L29615`）。
- **影响**：点“桌面沙盒”得到虚拟机，预期错位；文档不可信。

#### A-21【低·体积】备份与应用素材混入分发
- **证据**：根目录 `Nexus OS 26.before.html`、3 个 `.bak-*` 合计 16.7MB；`apps\strata\index.html.bak-20261105-v262` 1.84MB；`apps` 合计 36.6MB，其中 `float` 27.3MB（`.build` 与 `assets` 重复）。
- **影响**：打包/上传/首包体积失控。
- **修复方向**：`.gitignore`/发布脚本排除备份与 `.build`；只保留运行必需。

## 5. 冲突与取舍：哪些优点不能直接搬

1. **“极简”不能直接搬成“功能少”。** FluentOS 的克制来自组件收口（FluentUI/FluentWindow/共享样式），不是删功能。Nexus 若照搬“少控件”，会变成“应用只有壳”。移植时先补宿主能力（FS/通知/设置/错误态），再谈视觉克制。
2. **“首屏预载”不能直接搬。** FluentOS 有 OOBE 缓冲，Nexus 直接进桌面；照搬 17MB 串行预载会把“打开就能玩”变成“打开就等”。Nexus 应反向做：壳先出、素材懒加载。
3. **“统一令牌”不能只搬文件。** FluentOS 的令牌之所以有效，是因为组件真的引用它；Nexus 把 `tokens.css` 引入却在主壳用 0 次 `var(--fs-*)`，只会多一层谎言。先替换高频硬编码，再谈“唯一真值源”。
4. **“后台冻结”不能只搬 CSS。** Nexus 大量应用是 iframe，父页的 `pointer-events:none` 冻不住 iframe 里的 `setInterval`；必须定义跨 iframe 的 pause 协议，否则只是把窗口变灰。
5. **“动效丰富”与“低配流畅”冲突。** FluentOS 252 处 `backdrop-filter`、Nexus 345 处，都是“好看但昂贵”。不能一边加材质一边要求低端机 60fps；需要材质分档 + `prefers-reduced-motion` + 低配降级。
6. **“登录安全”不能演一半。** 两个系统都把锁屏做成“安全边界”的视觉；但一个 PIN 明文、一个失败死链。要么明确“演示”，要么真做凭据，不能停在中间。
7. **“本地优先”与“联网能力”冲突。** Nexus 的天气/音乐/方哩方哩都依赖外网，却宣传“不联网”；FluentOS 至少把联网依赖写进 README。取舍可以是联网，但必须标注“需要网络”，并给离线降级。
8. **“应用数量”与“应用深度”冲突。** Nexus 用 24 个应用/36.6MB 堆出“生态感”，但 Reelix/Strata/VN/Necta/FangWork 都是壳；FluentOS 14 个应用但每个有真实数据流。发布级应优先“少而真”，不是“多而空”。

## 6. 避雷规则清单（可直接写进开发规范）

### 6.1 禁止

- **禁止**用 `innerHTML` 拼接任何用户可控字符串（文件名、标题、消息、应用名）；统一 `textContent`/`escapeHtml`。
- **禁止**静默截断/改写用户数据；任何降级必须可见、可导出、可撤销。
- **禁止**“只写不读”的设置项进入发布版；每个设置必须有消费者与验收用例。
- **禁止**用固定 `setTimeout` 假装网络/安装/更新（`installDelay=5000`、`620ms` 检查更新）。
- **禁止**把 `allow-same-origin` 与 `allow-scripts` 同时给第三方/沙盒 iframe。
- **禁止**用 `localStorage.clear()` 做“恢复出厂”；只删本应用前缀键。
- **禁止**在 UI 承诺“隔离/即焚/真实捕获/密钥不出宿主”，除非代码路径可证明。
- **禁止**把“演示数据”混入真实列表而不标注；演示模式必须有横幅/角标。
- **禁止**在 `file://` 或跨目录场景依赖相对 `../` 资源；分享包必须自包含。
- **禁止**提交 `.bak-*`、`before.html`、`__p_*` 探针页与重复 `.build` 目录。

### 6.2 必须

- **必须**为每个持久化写入返回结果，并由 UI 呈现成功/失败（保存状态不能靠 optimistic 文案）。
- **必须**为窗口/布局/播放/计时/游戏进度定义持久化字段与恢复策略（刷新后行为可预期）。
- **必须**为每个联网请求加超时、状态码判断、重试与页面内错误态。
- **必须**为模态/抽屉/菜单实现 `role/aria-modal/labelledby` + focus trap + Esc + 焦点归还。
- **必须**给 Dock/窗口/菜单/设置提供完整键盘路径（Tab/方向键/Enter/Esc），并在 a11y 规范中列为可判定条款。
- **必须**让主题令牌成为唯一来源：新代码只允许 `var(--fs-*/--r-*/--sp-*/--dur-*)`，禁止硬编码字号/圆角/阴影/hex。
- **必须**让四套皮肤有明确的“适配/未适配”清单；未适配应用显示统一降级外观，不允许各写一套。
- **必须**在发布前跑“死开关/死按钮/空引用/资源 404/备份文件”自动检查。
- **必须**在 README 与 UI 中区分“真实能力 / 模拟能力 / 规划中”，三者不能混写。

### 7.2 FluentOS：这些坑绝对不要踩

1. **不要把“为了启动性能”做成“静默丢用户数据”**（F-02）。要快就换存储，不要改内容。
2. **不要用 optimistic 文案替代保存结果**（F-03）。这是最容易被用户记恨的一类 bug。
3. **不要把安全开关做成装饰**（F-04/F-05）。要么真做，要么明说演示。
4. **不要用 `innerHTML` 渲染任何名字**（F-01）。一次注入就能读走全部本地数据。
5. **不要让“后台冻结”只冻 CSS**（F-06）。CPU 不会因为 `pointer-events:none` 停下来。
6. **不要让组件库只做外观不做 a11y**（F-07）。模态是系统级组件，缺口会全站扩散。
7. **不要用固定延时假装网络**（F-10）。伪系统的“演示”必须可识别。
8. **不要给第三方 iframe 同时开同源与脚本**（F-11）。那不是隔离，是授权。

## 附：可直接复现的关键步骤

1. **FluentOS XSS**：启动本地 HTTP 服务 → 打开文件应用 → 重命名文件为 `<img src=x onerror=document.title='xss'>` → 回桌面 → 刷新。
2. **FluentOS 截断**：导入 >128KB 图片 → 关闭浏览器 → 重开 → 打开该文件（内容为空）。
3. **FluentOS 假保存**：DevTools 把 localStorage 配额占满（或开隐私模式）→ 记事本输入 → 等“已自动保存” → 刷新。
4. **Nexus 幽灵窗口**：开设置 + 文件 → 关文件 → F5 → 文件窗口回来。
5. **Nexus 死开关**：设置 → 个性化 → 动画速度切“快” → 开/关窗口，动画时长不变；控制中心音量拖到 0，系统提示音仍响。
6. **Nexus AI 密钥**：打开 `apps\agent.html` → 选择 OOBE 默认 API → 输入框出现 Key → 发一条消息 → Network 里看 `Authorization` 头。
7. **Nexus 虚拟机**：打开虚拟机 → 在虚拟系统里“恢复出厂” → 回宿主刷新，账户/文件是否还在。
8. **Nexus 小游戏**：打开小游戏合集 → 点“贪吃方” → 看到的是介绍页 → 再点“开始游戏”才进入。
