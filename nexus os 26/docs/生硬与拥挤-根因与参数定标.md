# 生硬与拥挤：根因与参数定标

> 对象：**Nexus OS 26**（`nexus os 26/Nexus OS 26.html` + `ui/*.css` + `ui/*.js`） vs **Fluent OS**（`D:\20533\Desktop\FluentOS-On-Web`）
> 方法：静态 CSS 参数抽取 + headless Edge(CDP) 运行时截图/计算样式/`getAnimations()` 快照/rAF 帧间隔采样

> 原始数据：[css-metrics.json](evidence-生硬与拥挤/css-metrics.json)、[runtime-fluent.json](evidence-生硬与拥挤/runtime-fluent.json)、[runtime-nexus.json](evidence-生硬与拥挤/runtime-nexus.json)

## 一、结论先行

**用户的原话问题是"为什么人家那么舒适、有呼吸感，我们的那么生硬、那么拥挤"。答案不是"人家间距更大"，而是下面 5 条，按致命程度排序：**

1. **我们一个物体的入场被拆成 4 条互不同步的过渡，人家是 1 条同步的关键帧。**
   `#smTileMenu` 同时跑 `opacity .34s ease` / `transform .46s` / `filter .34s ease` / `visibility 0s .34s`（[n26-startmenu.css:384-394](file:///D:/20533/deskbox/files/%E5%B0%8F%E6%96%B9%E8%A7%84%E5%88%92/%E5%B0%8F%E6%B8%B8%E6%88%8F/nexus%20os%2026/nexus%20os%2026/ui/n26-startmenu.css#L384-L394)）。同一块面板被读成"三段动作叠在一起"，这就是"加戏感"的来源；Fluent 的开始菜单是 1 个 `@keyframes startMenuOpen` 300ms 同时演 `opacity + translateY(20px) + scale(.95)`（[animations.css:281](file:///D:/20533/Desktop/FluentOS-On-Web/css/animations.css#L281)），只有一条节奏。

2. **位移量与时长严重失配：只走 18px 却给 520ms，曲线还是 expo-out。**
   磁贴入场 `translate: -14px 18px → 0 0`、`0.52s cubic-bezier(0.16,1,0.3,1)`（[n26-startmenu.css:358-374](file:///D:/20533/deskbox/files/%E5%B0%8F%E6%96%B9%E8%A7%84%E5%88%92/%E5%B0%8F%E6%B8%B8%E6%88%8F/nexus%20os%2026/nexus%20os%2026/ui/n26-startmenu.css#L358-L374)）。expo-out 在 25% 处已走完约 90% 距离，剩下 390ms 只有不到 2px 的爬行——**第一帧"啪"一下、后面"死了一样"**，既硬又拖。Fluent 对应位移是 20px / 300ms / 标准曲线，位移相近、时长少 42%。

3. **错落节奏低于人眼感知阈值：26ms × 25 块 = 等于没错落。**
   `animation-delay: calc(var(--smt-i) * 26ms + 70ms)`（[n26-startmenu.css:374](file:///D:/20533/deskbox/files/%E5%B0%8F%E6%96%B9%E8%A7%84%E5%88%92/%E5%B0%8F%E6%B8%B8%E6%88%8F/nexus%20os%2026/nexus%20os%2026/ui/n26-startmenu.css#L374)）。实测 25 个磁贴的 delay 是 70/96/122/148/…/668，步长 26ms；可用台阶是 50–80ms。26ms 的结果是 25 块几乎同时起跑，整体读作"一次糊上来"，而不是代码注释里写的"一块接一块推过来"。

4. **全屏接管 + 元素数 4 倍：我们把 100% 屏幕塞了 270 个元素，人家在 24.7% 屏幕里放 68 个。**
   实测启动台 `rect 1440×900`、`padding 30px 46px 22px`、内部可见元素 **270**；Fluent 开始菜单 `rect 600×533 @(420,287)`、`padding 24px`、内部可见元素 **68**。→ 屏幕占比 **100% vs 24.7%**，元素数 **270 vs 68**。

5. **间距"平铺化"：我们没有"紧-松"对比，所有东西等距，所以再大也挤。**
   桌面相邻间距：Nexus `P10 6 / 中位 16 / P90 25`（动态范围 4.2×）；Fluent `P10 2 / 中位 2 / P90 16`（动态范围 8×）。Fluent 是"文字内部 2px 紧贴、区块之间 16px 断开"的双峰分布（有分组就有呼吸）；我们是 6–25px 的均匀铺开（没有分组就没有呼吸）。同时字号 `12→14→20` 断档、`42/44px` 冗余，两层错误同时发生。

**"生硬"的具体来源（可归因，不是形容词）：**
- 时长太短：中位 220ms vs 300ms；
- 曲线用错：`ease-out` 占 53.5%（160–200ms 的 ease-out = 起步极快、结尾急停，手感"脆/硬"），而人家 63.6% 是 `ease`（两头留时间）；
- 位移与透明度不同步：`opacity .34s` 与 `transform .46s` 各走各的；
- 有蓄力无回弹：`dockBounce` 有 0.30 的 −36px 过冲（[Nexus OS 26.html:3880-3886](file:///D:/20533/deskbox/files/%E5%B0%8F%E6%96%B9%E8%A7%84%E5%88%92/%E5%B0%8F%E6%B8%B8%E6%88%8F/nexus%20os%2026/nexus%20os%2026/Nexus%20OS%2026.html#L3880-L3886)），但入场动效全是一条单调 expo-out，没有回弹段。

> 口径说明：headless 无垂直同步，rAF 间隔均值（avg）**不能当帧率读**；只用 `maxGap` 与 `>16.7ms / >33.4ms` 帧数代表主线程阻塞。

**三次关键界面的还原时间线：**

- **桌面 → 窗口打开（Nexus）**：`t=0` 调 `openApp('calculator')` 注入窗口 → `t≈0–55ms` 单帧 54.7ms（同时启动 `windowOpenGlass` 的 `filter: blur(4px)→0` 300ms，每帧重绘整窗内容）→ 窗口内 `backdrop-filter` 首次栅格化 → 140 帧内 6 帧 >16.7ms。**Fluent 同场景是 250ms `scale(.9)→1 + opacity`，帧内 4 帧 >16.7ms。**

## 三、根因排序清单（按"改了收益最大"排）

### R1｜错落节奏 26ms → 目标 60–70ms（收益最大，1 行改动）
- **现象**：启动台 25 块磁贴"一次糊上来"，看不出先后。
- **证据**：[n26-startmenu.css:374](file:///D:/20533/deskbox/files/%E5%B0%8F%E6%96%B9%E8%A7%84%E5%88%92/%E5%B0%8F%E6%B8%B8%E6%88%8F/nexus%20os%2026/nexus%20os%2026/ui/n26-startmenu.css#L374) `calc(var(--smt-i) * 26ms + 70ms)`；实测 delay 序列 70/96/122/…/668（步长 26ms，25 项）。
  代码注释自己也写错了账：[n26-startmenu.css:372](file:///D:/20533/deskbox/files/%E5%B0%8F%E6%96%B9%E8%A7%84%E5%88%92/%E5%B0%8F%E6%B8%B8%E6%88%AF/nexus%20os%2026/nexus%20os%2026/ui/n26-startmenu.css#L372) 写"一屏十几块，收尾约 0.9s"，实际 **25 块、尾块 694ms 起步、1214ms 才结束**。
- **参数目标**：`stagger = 60ms`；25 项时改为"分 3 批，批内 60ms、批间 140ms"，总时长控制在 **≤900ms**；或磁贴数 >16 时改用"扇区扫描"（按行/按列 stagger）。
- **验收**：第 1 块与第 25 块的起跑差 ≥ 600ms 且 ≤ 1000ms。

### R2｜18px 位移 / 520ms expo-out → 位移与时长的比例定标
- **现象**：首帧猛冲、后 400ms 几乎静止，手感"硬 + 拖"。
- **证据**：[n26-startmenu.css:358-374](file:///D:/20533/deskbox/files/%E5%B0%8F%E6%96%B9%E8%A7%84%E5%88%92/%E5%B0%8F%E6%B8%B8%E6%88%8F/nexus%20os%2026/nexus%20os%2026/ui/n26-startmenu.css#L358-L374)（`translate: -14px 18px → 0`，`0.52s`）。
- **参数目标**（速度定标，不是拍脑袋）：
  - 位移 ≤ 24px → **180–240ms**；
  - 24–80px → **260–320ms**；
  - ≥ 80px → 360–420ms + 允许一次回弹。
  - 曲线：短位移用 `cubic-bezier(.2,.9,.3,1)`，**不要用 expo-out**（expo-out 只适合"从屏幕外飞入"的大位移）。
- **参考**：Fluent 20px/300ms（`startMenuOpen`，[animations.css:258-281](file:///D:/20533/Desktop/FluentOS-On-Web/css/animations.css#L258-L281)）。

### R3｜一个物体 4 条不同步过渡 → 收敛成 1 条同步入场
- **现象**：面板入场读作"三段动作"。
- **证据**：[n26-startmenu.css:384-394](file:///D:/20533/deskbox/files/%E5%B0%8F%E6%96%B9%E8%A7%84%E5%88%92/%E5%B0%8F%E6%B8%B8%E6%88%8F/nexus%20os%2026/nexus%20os%2026/ui/n26-startmenu.css#L384-L394)（opacity .34s / transform .46s / filter .34s / visibility 0s .34s）；运行时快照 `smTileMenu` opacity 340ms + transform 460ms，曲线还不同（`ease` vs `cubic-bezier(.2,.9,.3,1)`）。
- **参数目标**：`opacity + transform` 一条 `@keyframes`，**统一 280ms / `cubic-bezier(.16,1,.3,1)`**；`filter` 单独 **≤180ms** 且只在 `transform` 的前 60% 区间；`visibility` 用 `0s`（不加延迟，避免关闭时"影子还在"）。
- **验收**：`document.getAnimations()` 里该元素只有 1 条 running（不含环境循环）。

### R4｜单屏元素数 270 → ≤140（全屏启动台的正确定性）
- **现象**：不是"间距小"，是"一屏要读的东西是人家 4 倍"。
- **证据**：`runtime-nexus.json startMenu`：`rect 1440×900`、`padding 30px 46px 22px`、`elementCount 270`；对照 Fluent `rect 600×533`、`padding 24px`、`elementCount 68`。
- **参数目标**：全屏启动台保留（这是取向，见第五节），但按分区降熵：
  - 首屏只放 **≤ 16 个磁贴** + 1 个搜索框 + 1 个"全部应用"入口（其余进二级/分组页）；
  - 单屏可见元素 **≤ 140**（= Fluent 68 的 2 倍上限）；
  - 分组之间留 **≥ 32px** 的空白带（现在整屏 padding 只有 30/46px，磁贴之间无分组呼吸）。
- **验收**：`elementCount` 从 270 降到 ≤140；磁贴间 `gap` ≥ 12px、分组间 ≥ 32px。

### R5｜间距平铺化（4.2× 动态范围）→ 建立双峰间距
- **现象**：所有东西等距，视觉没有分组边界 = 拥挤。
- **证据**：桌面 gap `P10 6 / 中位 16 / P90 25`（4.2×）；Fluent `P10 2 / 中位 2 / P90 16`（8×）。CSS 层：我们 4px 基准命中 40.5%、8px 19.1%（Fluent 52.5% / 26.5%）。
- **参数目标**：
  - 文字内部/图标与文字：**2–4px**（要"紧贴"）；
  - 同组控件之间：**8px**；
  - 组与组之间：**24 或 32px**（要"断开"）；
  - 面板内边距：**20–24px**（控制中心现在 14px）；
  - `P90/P10` 比值目标 **≥ 7×**（当前 4.2×）。
- **验收**：新的间距分布出现 4px 与 24px 两个峰；4px 基准命中率 ≥ 70%。

### R6｜字号断档 + 冗余 → 6 档正文 + 1 档显示
- **现象**：正文 `12→14→20` 断档（14 到 20 之间没有过渡级），显示级 `42/44` 两档几乎相同（差 2px，肉眼不可辨却占一个层级）。
- **证据**：`runtime-nexus.json desktop.fontSizes` = `10 / 10.5 / 11 / 12 / 14 / 20 / 24 / 34 / 42 / 44`；CSS 层字号刻度 **59 种**，最短相邻差 **0.5px**（10→10.5）。
- **参数目标**：正文 **11 / 12 / 14 / 16**；小标题 **18**；大标题 **24**；显示 **40**（并删掉 42/44 中的一档、删掉 10.5）。
  - 相邻级差目标：正文 **1–2px**，跳级 **≥ 4px**；同一页面 ≤ 8 档。
- **验收**：字号 distinct 值 ≤ 12（当前 59）。

### R7｜多层阴影 39.6% → ≤15%
- **现象**：多个窗口/面板边缘发灰，边界读不清。
- **证据**：多层阴影 393/994 = 39.6%，最大 8 层；Fluent 31/189 = 16.4%，最大 4 层。桌面 Dock 计算值 `rgba(0,0,0,.15) 0 -10px 25px inset + rgba(255,255,255,.45) 0 1px 0 inset`，再叠 `url(#n26LgDock)+blur+grain`。
- **参数目标**：浮层统一 **1 层外阴影** `0 8px 32px rgba(0,0,0,.12)`（或 0.14）+ **1 条 1px 内高光**；禁止 3 层以上；`backdrop-filter` 每屏 ≤ 3 个元素（现在 8）。

### R8｜160–200ms 的 ease-out 密集出现 → 按用途分级时长
- **现象**：所有交互都"啪"一下（中位 220ms、ease-out 53.5%）。
- **证据**：CSS 时长直方图 `160ms ×157`、`200ms ×178`、`150ms ×109`；easing `ease-out ×633`。
- **参数目标**：
  - 纯反馈（hover/press/开关）：**80–120ms**，`ease-out`；
  - 入场（面板/菜单/窗口）：**260–320ms**，`cubic-bezier(.16,1,.3,1)`；
  - 退场：**180–220ms**，`cubic-bezier(.4,0,1,1)`（比入场快、更平直）；
  - 状态保持类（颜色/主题）：**200–250ms** `ease`，不要和位移同跑。

## 五、哪些是设计取向差异、不必改

1. **全屏启动台 vs 600px 浮层**：这是产品取向，**不要照搬 Fluent 的 424–600px 浮层**。全屏要治的是"降熵"（R4：元素 ≤140、分区留白 ≥32px），不是缩成小窗。
2. **Dock 更大更圆（34px radius / 28px 图标）**：取向，保留。
3. **组件在左侧（Nexus）vs 右侧（Fluent）**：取向，保留。桌面文本覆盖率 1.9% vs 1.8%，**桌面本身并不更挤**，不要为了"呼吸感"去砍桌面组件。
4. **Fluent 的 300ms `ease` 偏慢**：在高频操作（磁贴拖拽排序、开关连点）上并不合适；我们的快节奏在"按住拖动"场景是对的，**只有"入场"不该用这个节奏**。
5. **10.5px 字号**：若确有 125%/150% DPI 密排设计，可保留；**若无 DPI 分支，就是噪声**，建议按 R6 收敛（此项需产品确认，不强行判死）。
6. **Nexus 的 Win10 式磁贴边缘光**（[n26-startmenu.css:396-399](file:///D:/20533/deskbox/files/%E5%B0%8F%E6%96%B9%E8%A7%84%E5%88%92/%E5%B0%8F%E6%B8%B8%E6%88%8F/nexus%20os%2026/nexus%20os%2026/ui/n26-startmenu.css#L396-L399)）：人家没有，属我们的风格资产，保留。
7. **环境循环动画（9 条 3.4–10.5s 的 covi 呼吸）**：这是"呼吸感"的正资产，**不要为了降并发砍掉**；它不参与入场节奏。

## 附录 A｜测量方法与口径

- **静态参数**：`analyze-css.js` 解析两侧 CSS（Fluent `css/*.css`；Nexus 主壳全部内联 `<style>` + `ui/*.css`（排除 `.bak`）+ `fangui/core/*.css` + 主壳 `<link>` 的本地 CSS，共 43 个来源 / 40332 条声明）。
- **运行时**：`capture.js` 用 CDP 直连 headless Edge，`Page.addScriptToEvaluateOnNewDocument` 预置初始化屏障（Fluent `fluentos.oobe_completed`；Nexus `n26:installed` / `n26fb_done`），`Emulation.setDeviceMetricsOverride(1440×900, DPR 1)`，`--mute-audio`。
- **动效快照**：动作后 60ms 取 `document.getAnimations()`，记录 `effect.getComputedTiming()` 的 duration/delay/easing/playState，**只统计 `state === "running"`**（`finished` 的 CSS 动画会留在列表里，不过滤会把并发数放大 3–5 倍）。
- **帧采样**：`requestAnimationFrame` 记录相邻时间差，取 `maxGap / >16.7ms 帧数 / >33.4ms 帧数 / 均值`。
- **密度**：可见元素（`rect>1×1`）、纯文本叶节点、文本覆盖面积比、shadow/backdrop-filter/radius/border 元素数、相邻间距 P10/中位/P90、`scrollH`。

## 附录 B｜已知局限（未测到就写未测到）

| Fluent 设置窗口精确 rect / 行高 | **未测到** | `settingsPanel/.settings-panel/[data-app=settings]` 均未命中 |
